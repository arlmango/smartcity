# Дизайн SmartCity

## Референс
Смотри design/SmartCity-3D-Astana.png. Это композиция продукта с реальными OSM-контурами в районе EXPO; не источник расписаний, возможностей мест и точных высот. Свидетельство исходного макета в design/3d-evidence.json: 279 контуров, только 7 высот из height, 164 из этажности, 108 defaults. Эти числа относятся к старому макету, не к будущей production базе. Пересчитать по новому ingest.

## Визуальная система
Название исключительно SmartCity. Палитра: graphite #17201C, warm white #F6F7F2, lime #D9F66F, muted text #59645D, strokes #DDE4DC. Цвета корректировать по реальному контрасту. Шрифт с хорошей кириллицей, например Manrope/Inter с доступной лицензией; не обязательный внешний запрос, self-host где возможно.

8px spacing scale; компактная, но не тесная типографика; radius 16–24 для крупных панелей, 10–14 для контролов; лёгкие тени, без стеклянных слоёв, мешающих читать карту. Лайм только для primary CTA/selected markers, не для мелкого текста. Категории имеют иконку+подпись, цвет не единственный сигнал.

## Desktop
Узкая навигация сверху: логотип, «Астана», краткая формулировка задачи, информация о данных. Основная карта на весь оставшийся экран. Левая панель ~360–400px: «Куда пойдём?» → текущая точка → свободный запрос → время → возврат → CTA. После результата панель превращается в компактный summary + 1–3 карточки. Карта сохраняет видимые landmarks, контролы справа, attribution снизу. Выбранная карточка и marker подчёркнуты согласованно. Не перегружать карту случайными рекламными POI.

## Mobile
Карта выше/за bottom sheet, два-три фиксируемых состояния панели без захвата всего touch scrolling. Переключение «Карта / Список» доступно. CTA не перекрывает source/attribution. Высота экрана учитывает safe areas и мобильную клавиатуру. Контролы не уходят за экран при длинных названиях.

## Контент
Короткие русские формулировки: «40 минут», «Вернуться сюда», «Выбрать точку», «По прямой», «Время приблизительное», «Часы не указаны», «Наличие розеток не подтверждено». Важные unknowns рядом с рекомендацией, а не только в футере. Не писать «идеально подходит» при неподтверждённом обязательном условии.

## Движение
Только функциональное: fly-to выбранного места, появление карточек, плавный переход2D/3D. Не крутить город бесконечно. Reduced-motion отключает camera animation. Пользователь может прервать перемещение камеры.

## Что не делать
Не превращать главную в лендинг, где надо искать карту. Не выдавать raster-референс за работающий UI. Не вставлять декоративные цены, звёзды, «открыто сейчас» или маршруты. Не делать 3D настолько ярким, чтобы исчезали улицы/подписи/выбор точек. Не скрывать ошибки сети пустым canvas.
