## 4. Что сделано
**Выбор функции.** P0 прошёл на реальном роутере → выбран Timebox Walk. Резерв «короче / интереснее» не строился;
двух независимых вариантов с сравнением (PR #2) достаточно как запасной режим, когда плана нет.

**Сервер** (`services/api/smartcity_api/services/plan.py`):
- Пул — до 5 мест из уже отфильтрованного жёсткими условиями и ранжированного списка (с той же диверсификацией),
  только те, у которых собственная ходьба туда-обратно ≤ 60% бюджета. LLM не участвует.
- Участки между местами — только от роутера: ≤ 20 вызовов, этап ≤ 4 с; сбой роутера → плана нет (частичный не показывается);
  «нет пути / подход > 100 м» → эта пара не используется, прямая не подставляется.
- Перебор 2–3 упорядоченных остановок (≤ 85 последовательностей), детерминированно. Бюджет = ходьба (ceil секунд роутера +
  оценка подхода) + визиты (типичные для категории; при нехватке — сокращаются, но не ниже минимума) + запас max(5, 10% ходьбы);
  обратный путь — если просили. Не больше одного места «поесть». Часы работы проверяются на время прихода по плану;
  при «должно быть открыто» неизвестные часы не проходят.
- Нет плана → `plan_note` с настоящей причиной: время (с минимально нужным бюджетом), закрыто к приходу, нет путей, только еда.
- Контракт: `RecommendResponse.plan: WalkPlan | null`, `plan_note`. Названия и координаты — из БД.

**Интерфейс**: карточка плана первой в результатах; остановки, «пешком ≈ / на месте ≈», обратный путь, итог, честная
фраза «Время примерное…»; одна основная кнопка «Показать план на карте»; «Почему такой план» свернуто. План и отдельное
место взаимоисключающи на карте; номера остановок не конфликтуют с номерами карточек. «Убрать» повторяет ровно тот запрос,
что построил план, с одним исключённым местом (и во время генерации объяснений). Смена старта помечает план устаревшим.
Невалидный план отбрасывается на клиенте с заметкой, карточки остаются.

## 6. Демо-скрипт (60–90 с)
1. «Покрываем район EXPO / MEGA, не всю Астану». Демо-точка, «60 мин», «Хочу погулять и посмотреть интересные места».
2. Через несколько секунд — «План на 60 мин: 2 остановки, ≈ 60 мин, 1,4 км». На карте — линия по пешеходным дорожкам
   и обратный путь пунктиром. «Время примерное; подход к месту не проверен».
3. «Почему такой план»: пешком 25–27, на местах ~30, запас 5; кто не вошёл и почему.
4. «Убрать» первую остановку. Это **новый подбор** без этого места (остальные условия те же), а не правка старого плана:
   над результатом появляется заметка — «Подобран новый план без «…»; в него вошли другие места: …» или
   «Без «…» план не собрался» и «Среди найденных вариантов не удалось собрать прогулку на это время».
5. Без плана остаются отдельные места с тем же расчётом; ИИ дописывает объяснения позже (на CPU — десятки секунд).
Не говорить: «мгновенно», «доступно для колясок/безопасно», «вся Астана», «проверено на iPhone».

## 8. Известные ограничения
- План перебирает только 5 лучших кандидатов, поэтому при отказе не называется «минимально нужное время» —
  только «среди найденных вариантов не удалось собрать прогулку на это время».
- Состав плана зависит от времени старта (часы работы на момент прихода): прогоны 19.10 вечером и 20.10 утром различаются.
- Метки остановок частично перекрываются, если концы участков ближе ~100 м.
- Время на местах — типичное для категории, не факт; запас фиксированный.
- Облачный граф меньше Mac-графа (только highway в прямоугольнике покрытия).
- Проверено только в эмуляции Chromium; WebKit/Firefox по этой функции не запускались.
