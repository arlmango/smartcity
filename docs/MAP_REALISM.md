# Карта: реалистичнее и понятнее (20.10.2026)

Ветка `claude/map-realism-20261020` от `4cb6f98` (ветка PR #3 — маршрутизация и Timebox сохранены).
Ориентир — читаемость больших городских карт: иерархия улиц, спокойные объёмы, мало подписей. Материалы, тайлы,
модели и фирменный стиль 2ГИС не использовались. Доказательства: `artifacts/map-realism/`.

## 1. Подложка
- Настоящая подложка — Protomaps Basemap (OSM, ODbL), извлечение города тем же `go-pmtiles 1.31.2`, что и `make basemap`.
- **Свои тайлы зданий стали необязательными.** Если `astana-buildings.pmtiles` (Geofabrik: источник высоты, части,
  формы крыш) нет, карта выдавливает слой зданий OSM из самой базовой карты: `height`/`min_height`, где они есть,
  `building_part`; без высоты — условно 10 м, светлее и полупрозрачно. `/api/basemap` сообщает `building_tiles: own|base`,
  статистика своего архива без него не показывается, легенда говорит, откуда высоты.
- Почему так: в облаке Geofabrik недоступен (connection reset), зеркал Казахстана нет; Protomaps доступен.
  На Mac `make basemap` даёт полный путь со своими тайлами (формы крыш, источник высоты).

## 2. Объём и оформление
- Измеренная высота (OSM `height` или этажи) — сплошные стены, цвет по высоте или по OSM `building:colour`;
  оценки и условная высота — отдельный светлый слой. Формы крыш по `roof:shape` — только в своих тайлах.
- **Процедурные окна** (`lib/facades.ts`): три узора (малоэтажный, средний, стекло), только на измеренных высотах,
  с z15, только на высоком уровне детализации. Это стилизация: в легенде — «Окна на стенах — стилизация, не настоящие фасады».
- Мягкий тёплый свет (`intensity 0.28`), вертикальный градиент, нейтральные светло-серые крыши, мягкая контактная тень.
- Издалека (z11–13): основные улицы мягким янтарным, второстепенные белые, вода/парки; плоские контуры зданий с z12,
  объёмы с z13; подписи крупных объектов — только те, что Protomaps сам ранжирует как ранние (`min_zoom ≤ 13`).
  Ближе (z15+): подписи значимых мест, тротуары, окна. Названия районов — только из OSM (их немного; не выдумываются).

## 3. Байтерек и Нур Алем (`lib/landmarks.ts`)
Собственные облегчённые модели из срезов fill-extrusion: сфера — стопка дисков с радиусом по окружности, **не цилиндр**.

| | Из OSM | Стилизация |
|---|---|---|
| Байтерек | way/230401644: шар `roof:shape=orb`, верх 30 эт. × 3,2 м = 96 м, Ø 21,9 м по контуру, цвет `#C3B391`; way/230401645: монумент, 27 эт., Q804210 | белый ствол, 12 рёбер «кроны», постамент |
| Нур Алем | way/1461813334: `height=100`, круглый контур Ø 78,1 м (проверено в config/landmark_shapes.json); подиум way/1461813335 (6 м) остаётся из OSM | опора, полосы остекления |

Заменённые объекты скрываются в 3D по id (Protomaps v4: `2^45 + way id`; свои тайлы — новое свойство `oid`), в 2D
остаются настоящие контуры. Подпись на карте — «… · стилизация». Сторонние 3D-модели не искались и не использовались:
собственные модели целиком описываются данными OSM выше, вопросов лицензии не возникает (OSM — ODbL, атрибуция есть).
Публичные источники называют высоту Байтерека 97 м; модель следует разметке OSM (96 м).

## 4. Маршрут, подписи, маркеры
- Линия прогулки — с белой подложкой, толщина растёт с zoom; обратный путь — фиолетовый пунктир.
- А (начало пути на сети) — полое кольцо, Б и остановки плана — залитые; метки ближе 120 м разводятся на 32 px.
- Пока на карте результаты или маршрут, подписи мест и ориентиров скрываются: HTML-маркеры не участвуют в
  коллизии подписей MapLibre и иначе перекрывали бы их.

## 5. Слабые устройства (`lib/deviceTier.ts`)
«low»: сенсорный экран + ≤ 4 ядер, `deviceMemory ≤ 3`, Save-Data; `?detail=low|high` — ручное переопределение.
Низкий уровень: без окон и контактной тени, вдвое более грубые модели, плотность пикселей ≤ 1,5. 2D-режим сохранён.

## 6. Производительность (облако, Chromium headless, **программный рендер SwiftShader** — не телефон)
6-секундный пролёт камеры (`apps/web/scripts/map-views-live.cjs --perf-only`), кадров в секунду, без генерации модели
в фоне (ожидание простоя Ollama перед каждым прогоном). CPU 4× — эмуляция DevTools, GPU телефона не эмулирует.

| Конфигурация | Данные | fps 1× | fps 4× CPU |
|---|---|---|---|
| ДО, desktop 1440×900 | Protomaps + свои здания только EXPO | 9,1 / 9,8 / 9,9 | 6,5 / 6,4 / 6,4 |
| ПОСЛЕ high, desktop | Protomaps, здания всего города + окна | 7,4 / 6,9 | 5,1 / 4,9 |
| ПОСЛЕ low, desktop | то же без окон | 7,9 / 8,3 | 5,6 / 5,9 |
| ДО, телефон 390×844 DPR 3 | как выше | 5,2 / 5,0 / 5,3 | 3,8 / 3,7 / 3,9 |
| ПОСЛЕ high, телефон DPR 3 (`?detail=high`) | весь город + окна | 4,3 / 4,1 / 4,6 | 3,1 / 3,1 / 3,3 |
| ПОСЛЕ low, телефон (авто) | весь город, DPR 1,5 | 13,6 / 14,6 / 13,5 | 8,6 / 9,2 / 7,8 |

Вывод: на desktop «после» рисует весь город вместо одного района и медленнее на ~25 %; на телефоне автоматический
низкий уровень даёт ~в 3 раза больше кадров, чем «до». Абсолютные числа на реальном GPU будут другими — **на реальном
телефоне не измерялось**.

## 7. Не сделано / ограничения
- Свои тайлы зданий всего города (формы крыш, источник высоты) в облаке не собирались — нужен `make basemap` на Mac;
  тайлы, собранные до этой ветки, не содержат `oid`: старая стилизация Нур Алем скрывается, но OSM-объекты Байтерека
  в них совпасть с моделью не могут — пересоберите `make basemap`.
- Фотореализма нет и не обещается: фасады процедурные, крыши плоские там, где форма не размечена.
- Реальный телефон, WebKit/Firefox — не проверены.
