# SmartCity — пакет сдачи

SmartCity подбирает короткую прогулку по Астане. Пользователь выбирает точку старта и пишет, чего хочется. Сервис
возвращает 1–3 реальных места из собственной базы OpenStreetMap: с объяснением, временем дороги и посещения и пометками,
что не подтверждено. Под капотом семантический поиск по embeddings плюс геофильтр, а локальная языковая модель
объясняет только найденные места. Названия и координаты всегда берутся из базы, а не из ответа модели.

## Что нужно
- Docker Desktop (на Linux — Docker Engine с Compose), Git, [uv](https://docs.astral.sh/uv/), make.
- 8 ГБ RAM (комфортно 16 ГБ), 10–15 ГБ свободного диска, интернет для первой установки.
- Windows — только через WSL2 с Ubuntu (подробно в `docs/LOCAL_RUN.md`).

## Запуск (команды из `docs/LOCAL_RUN.md`)
```bash
git clone https://github.com/arlmango/smartcity.git   # ветка main
cd smartcity
make bootstrap                 # .env из .env.example, зависимости Python, база данных
CONFIRM=1 make models          # локальные модели ИИ: ~3,1 ГБ (qwen2.5:3b и bge-m3)
make ingest ARGS="--from-snapshot osm-20261018T200514Z"   # данные OSM из снимка в репозитории, без интернета
make basemap                   # тайлы карты всей Астаны: ~240 МБ загрузки, 2–3 мин (пересоберите, если тайлы старые — см. ниже)
make index                     # смысловой индекс мест
make up                        # запуск; затем http://localhost:3000
```
Готовность: `curl http://localhost:8000/api/ready` — у db, data, map, embeddings, llm должно быть `ok`.
Остановка: `make down` (данные и модели сохраняются).

### Пешеходные маршруты и «Прогулка на время» (необязательно)
План из 2–3 остановок и линии пути строятся только по локальному пешеходному графу Valhalla. Без него сервис честно
показывает расстояния по прямой и пишет, что план недоступен. Адаптер принимает только локальный адрес
(127.0.0.1), поэтому API нужно запускать на хосте — `make dev`, а не `make up`:
```bash
uv run --with osmium==4.3.2 python scripts/routing_snapshot_extract.py \
  --snapshot osm-20261018T200514Z --out data/routing/snapshot/astana-snapshot.osm.pbf
cp config/valhalla-pilot.json data/routing/snapshot/valhalla.json
docker run --rm --network none -v "$PWD/data/routing/snapshot:/data" ghcr.io/valhalla/valhalla:3.8.3 \
  valhalla_build_tiles -c /data/valhalla.json -j 1 /data/astana-snapshot.osm.pbf
docker run -d --name smartcity-route -p 127.0.0.1:8208:8002 -v "$PWD/data/routing/snapshot:/data:ro" \
  ghcr.io/valhalla/valhalla:3.8.3 valhalla_service /data/valhalla.json 1
# в .env (не коммитить): ROUTING_PROVIDER=valhalla, ROUTING_BASE_URL=http://127.0.0.1:8208,
#   ROUTING_GRAPH_VERSION=snapshot-osm-20261018T200514Z-valhalla-3.8.3
make dev                       # API :8000 и сайт :3000 на хосте
```
Граф из снимка покрывает только район EXPO / MEGA (дороги из снимка OSM). Так проверено в облаке (Linux amd64,
API на хосте); на Mac этими же командами не запускалось. Подробности: `docs/TIMEBOX.md`, `artifacts/routing-cloud/`.

## Три демо-сценария
1. **Кофе и прогулка рядом.** Нажмите «Демо-точку» (район EXPO) или кликните по карте внутри зелёной пунктирной зоны.
   Напишите «Хочу выпить кофе и немного погулять», выберите 40 минут, нажмите «Подобрать прогулку». Появятся 1–3
   карточки с теми же номерами, что на карте. Клик по маркеру открывает карточку, клик по карточке перелетает к месту.
2. **С возвращением и временем.** «Час с ребёнком, вернуться сюда». В бюджете учтены дорога туда, посещение, обратный
   путь и запас. Где детские условия не подтверждены источником, это сказано прямо. С включённым роутером сверху
   появляется «План на 60 мин» из 2–3 остановок с линией по пешеходным дорожкам; «Убрать» подбирает план заново без
   этого места и пишет, что изменилось.
3. **Честный отказ.** «Кофе с розеткой, 1 час». Наличие розеток в данных не подтверждено, поэтому сервис честно говорит,
   что подходящих мест нет, и предлагает ослабить условие. Ещё: клик вне зелёной зоны — «Вне зоны рекомендаций».

## Известные ограничения
- **Рекомендации только в районе EXPO / MEGA Silk Way** (126 мест). Карта показывает всю Астану, но база мест собрана
  только в этой зоне.
- **Карта стилизованная, не фотореалистичная.** Здания — объёмы по контурам OSM; окна на стенах — процедурная
  стилизация, не настоящие фасады. Высоты частично оценочные (в легенде). Формы крыш по `roof:shape` есть только в
  своих тайлах (`make basemap`); без них используются здания OSM из базовой карты Protomaps, где форм крыш нет.
  Байтерек и Нур Алем — упрощённые модели по данным OSM, подписаны «· стилизация».
- **Старые тайлы зданий нужно пересобрать: `make basemap`.** Тайлы, собранные до 20.10.2026, не содержат метку
  объекта `oid`. С такими тайлами старая стилизация Нур Алем скрывается, но исходные объекты Байтерека не
  совпадают с моделью — возможны двойные объёмы ориентира. После пересборки этот риск не проверялся на Mac.
- **Маршрутизация — только локальный пилот** (см. выше). Без него расстояния по прямой и время ориентировочное.
  Граф OSM не подтверждает доступ на местности (входы, переходы).
- Ответ ИИ на обычном процессоре — 30–90 с; найденные места видны раньше объяснений.
- По умолчанию (`APP_USAGE_MODE=commercial`) только схема. Спутниковый слой EOX доступен только при
  `APP_USAGE_MODE=noncommercial` и только после согласия пользователя.
- Проверено в эмуляции Chromium (desktop и ширины 360/390/430). **На реальных телефонах не проверялось**, в том числе
  плавность карты; WebKit/Firefox для плана и новой карты не запускались.
- В CI шаг `live-smoke` пропускается настройками — это **не проверка живой модели**. Живая модель и роутер
  проверялись вручную в облаке (`artifacts/routing-cloud/`), не в CI.

## Что в архиве исходников
ZIP — это **исходный код** для установки по командам выше, а не автономная готовая сборка.
- **Включено:** код (web, API, ingest), конфиги, Docker-файлы, тесты, документация, снимок данных OSM
  `data/snapshots/osm-20261018T200514Z`, слои карты района `data/map/*.geojson`, манифест и граница города
  `data/basemap/manifest.json`, `astana-boundary.geojson`.
- **Не включено:** `.env` и любые секреты (создаются из `.env.example`), `node_modules` и `.venv` (ставит
  `make bootstrap`), модели ИИ (~3,1 ГБ — `make models`), тайлы карты `*.pmtiles` (~14 МБ — `make basemap`),
  кэши и тяжёлые артефакты проверок: скриншоты и логи `artifacts/clean-install`, `artifacts/live`,
  `artifacts/map-redesign`, `artifacts/screenshots`, `artifacts/map-realism`, `artifacts/routing-cloud`. Они остаются в
  репозитории.
