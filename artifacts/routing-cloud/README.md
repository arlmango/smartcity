# Облачная проверка маршрутизации и плана «Прогулка на время» (19.10.2026)

Всё здесь получено из запущенного приложения в облачном контейнере (Linux amd64, 4 CPU, 15 GiB RAM, без GPU).
Это не Mac-пилот из `artifacts/routing-pilot/`: граф пересобран из **закоммиченного** снимка OSM.

## Что было запущено
- БД: `scripts/ingest.sh import --from-snapshot osm-20261018T200514Z` → 126 мест; `scripts/index.sh` (bge-m3, 126 векторов).
- Модели: Ollama 0.12.6, `bge-m3`, `qwen2.5:3b` (CPU).
- Роутер: Valhalla `ghcr.io/valhalla/valhalla:3.8.3` amd64
  (`sha256:70b45295d81035e3562e1bbf996a28d5fc55e1ccc5d7e3fff9f297d3b1a1359f`; пиннутый в пилоте digest — только ARM64).
  PBF собран `scripts/routing_snapshot_extract.py` из `data/snapshots/osm-20261018T200514Z/map_roads.json.gz`:
  5 310 путей highway, 22 716 узлов, 215 102 байт, только прямоугольник покрытия EXPO/MEGA (меньше Mac-извлечения ~111 км²).
  Сборка: `--network none --memory 2g --cpus 2`, exit 0, ≈3,2 с, тайлы 2,3 MiB (`build.log`).
  Сервис только на `127.0.0.1:8208`. `ROUTING_GRAPH_VERSION=cloud-snapshot-osm-20261018T200514Z-valhalla-3.8.3`.
- API `127.0.0.1:8108` (`ROUTING_PROVIDER=valhalla`), web standalone `127.0.0.1:3208`.
- Базовая карта города (Protomaps pmtiles) в этом прогоне **не собрана**, поэтому на скриншотах фон карты пустой —
  это не демо. Прогон с настоящей подложкой: `basemap-20261020/`.
- Тексты отказа на этих снимках («нужно хотя бы N мин») сняты на `141923d`; формулировка потом заменена,
  потому что перебираются только 5 кандидатов (актуальные тексты — `basemap-20261020/`).

## Время (не SLA; маленькая выборка, показаны сами значения)
Первые карточки (preliminary) в браузере: 2,2–8,4 с по разным прогонам; финальный ответ модели: 23–76 с.
Значения после первого прогона выше, потому что предыдущая генерация на том же CPU ещё шла.
Маршрутизация кандидатов 0,8–1,8 с, участки плана 0,23–0,30 с (`timings_ms.routing` / `plan_routing`).
